## How it was done

Six read-only reviews covered formats and write safety, the story system, character data,
the application layer, world and environment, and tests and documents. The findings marked
below were then checked again.

| Mark | Meaning |
| --- | --- |
| **M** | Measured here: the real code run on an in-memory copy of a real save, values read back |
| **S** | Checked here against the source, line by line |
| **R** | Reported by one review, with its trace or measurement, and not checked again here |

Not one finding has been tried in the game. Nothing was clicked in the running program, so
UI findings are traces. KotOR 2 is not installed on this PC; its four saves exist, its
tables do not, so anything said of KotOR 2 rules is **unmeasured**, including where a review
said "both games". Mod content counts as known and is left out: the `slem*` and `liv_m99*`
modules have objects with no template.

Fixed during the audit, so not listed: the star map bug, the Leviathan's place, and a stage
skip that set the capture up a second time (CHANGELOG, `tests/star_maps.rs`).

## Tests

The structural gap: `game_running`, `is_xbox_save`, `read_only_reason`, `needs_game`,
`chapters_played` and `skip_path` are private to `src/main.rs`, so no test can reach them.
Most bugs in the story and refusal tables above live there.

- No test covers: the refusals, "stops if the backup fails", `backup_root`, or whether a
  backup is complete.
- `move_to_module`, `queue_transition`, `set_look`, `set_gender`, `add_power`, `remove_feat`,
  `copy_inventory`, doors, `import_npc`, Compare's Take and `remove_quest` are written by the
  editor with no read-back test. `move_to_module` carries the most risk.
- No real-save test asserts it checked anything, so a broken `find_saves` passes everything.
  `tests/level_grants.rs` and `tests/levels.rs` hide 11 of 27 saves by the name "KMRP".
- `tests/edits.rs:571` compares a value with itself. `levels_taken_away_newest_first` tests
  its own loop, not `rewind_level_history`, which Go Back runs.
- `played_through_copies_of_every_module` skips modules silently and needs only 50 to pass,
  and its `buildable` filter, added on 2026-11-02, uses the same lookups as the builder, so
  it can excuse a real loss. KotOR 2 has no such test.
- `a_chapter_does_not_pay_twice` prints item counts and asserts only credits.
- `tests/star_maps.rs` reads a missing global as 0, so its expected-0 cases cannot catch a
  misspelled name, and it has no Go Back case (findings 11, 12).

## Checked and found sound

- GFF and ERF round trips: 25 real KotOR 1 saves and 22,550 game GFFs read with no failure.
  Every literal field type in `src` matches the saves. Text encoding is an exact inverse for
  all 256 bytes.
- Backups never reuse a path, and a failed backup stops the write. Every write path reaches
  `write_files` after the game-running check.
- Global bit order and sizes, and `Mod_NextObjId0` above every id in the module read.
- Level up, level down, class add, remove and change reverse each other. No panic was found
  on a save with no class, empty lists, droids or non-Jedi.
- Story preview staleness: the plan is compared before it is applied.
- Tests write only to temporary copies.
